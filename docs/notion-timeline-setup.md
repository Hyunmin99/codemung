# Notion 작업 타임라인 연결

## 처음 설정하기

1. Notion에서 내부 연결(internal integration)을 만들고 콘텐츠 읽기·추가·수정 권한을 부여합니다. 사용자 정보 권한은 필요하지 않습니다.
2. 대시보드와 그 아래 원본 **프로젝트**, **작업 기록** 데이터베이스에 해당 연결의 접근 권한을 부여합니다.
3. 이 저장소의 Settings → Secrets and variables → Actions → Secrets에 `NOTION_TOKEN`을 저장합니다. 토큰을 채팅·코드·PR 본문에 넣지 마세요.
4. 같은 설정의 Variables 탭에 아래 두 값을 등록합니다. 실제 ID는 비공개 Notion 대시보드의 연결 안내에 있습니다.
   - `NOTION_ACTIVITY_SOURCE_ID`: 작업 기록 **data source** ID (database ID와 다릅니다).
   - `NOTION_PROJECT_PAGE_ID`: 이 저장소에 대응하는 프로젝트 카드의 page ID.
5. PR을 main에 병합합니다. Actions → Notion timeline → Run workflow를 실행하고 성공 여부와 Notion 기록을 확인합니다.
6. 이후 main에 push하면 자동 동기화합니다. Notion에 새 카드와 Push 수를 확인한 뒤 같은 실행을 재실행해 중복이 생기지 않는지 확인합니다.

## 첫 버전의 범위

- **main 브랜치만** 추적합니다. 기능 브랜치와 태그 push는 포함하지 않습니다.
- 날짜는 **한국 시간(Asia/Seoul)** 기준, GitHub가 push용 workflow run을 만든 시각입니다. 실제 작업 시간 또는 정확한 웹훅 수신 시각이 아닙니다.
- 프로젝트 × 날짜 카드 하나에 모읍니다. 각 push의 **마지막 커밋 메시지**와 실행 링크를 기록합니다. 모든 커밋을 분석하거나 AI 요약하지 않습니다. `커밋 수`는 추정하지 않고 비워 둡니다.
- `Push 수`는 이 워크플로를 실행시킨 고유 push 실행 수입니다. Actions 비활성화, skip-ci 커밋, GitHub 장애 등으로 실행이 생성되지 않은 push는 복원할 수 없습니다.
- 같은 실행을 재실행해도 run ID는 같으므로 중복 집계하지 않습니다.
- 동시 쓰기를 직렬화합니다. 대기 실행이 취소되어도 다음 실행이 최근 **7일 전 자정부터 오늘까지**의 push 실행 기록을 다시 집계합니다. 6시간마다 복구 동기화도 실행합니다. 예약 실행은 GitHub 사정에 따라 지연되거나 비활성화될 수 있습니다.
- 복구 기간에 1000건을 넘기면 부분 합계를 저장하지 않고 실패합니다. 실행 이력을 삭제하지 마세요. 복구 기간 밖의 실패는 별도 재처리가 필요합니다.
- 자동화 설치 이전의 커밋은 가져오지 않습니다. 과거 커밋 백필은 별도 작업입니다.
- 자동 생성 속성은 동기화 때 덮어씁니다. 개인 메모는 카드 **본문**에 적으세요. 진행 상태·다음 할 일은 변경하지 않습니다.

## 보안·운영

GitHub 토큰은 읽기 전용이고 checkout 인증은 보관하지 않습니다. 소스 파일과 diff는 Notion에 전송하지 않지만, 비공개 저장소의 마지막 커밋 메시지·링크·활동 날짜는 지정한 Notion 공간에 복사됩니다. 대시보드 공유 범위를 확인하세요.

연결 토큰은 해당 데이터베이스에만 접근하도록 설정하세요. Actions를 실행할 수 있는 저장소 변경 권한도 신뢰할 수 있는 사람에게만 부여하세요. 개인 저장소는 GitHub Actions 사용량 한도를 확인하세요.

`연동 중`은 최근 연결 성공을 뜻하며 실시간 상태 감시는 아닙니다. 이후 실패는 GitHub Actions 알림과 실행 로그에서 확인합니다. 중지하려면 Actions에서 이 워크플로를 Disable 하세요.
