# CodeMung 프로젝트 개요

## 한 줄 정의

Claude Code와 Codex가 일하는 상태를 한눈에 보여주고, 기다리는 동안 함께 멍때리는 macOS 데스크톱 컴패니언.

## 왜 만드는가

AI 코딩 에이전트와 일하는 흐름에는 필연적으로 "기다리는 시간"이 생긴다. 에이전트가 작업하는 동안 개발자는 터미널을 응시하거나, 다른 탭으로 도망가 컨텍스트를 잃는다. CodeMung은 이 대기 시간을 낭비나 불안이 아닌 **회복의 시간**으로 바꾼다.

이 방향은 리서치([research-mung.md](research-mung.md))로 뒷받침된다:

- 멍때리기는 뇌가 꺼진 상태가 아니라 디폴트 모드 네트워크(DMN)가 켜진 상태로, 창의성·기억 정리·문제 해결(부화 효과)을 담당한다.
- 부화 효과는 "충분한 몰입 → 저부하 휴식 → 복귀" 사이클에서 가장 크다. AI 에이전트 대기 시간은 이 사이클에 정확히 들어맞는 자연 발생적 휴식 구간이다.
- 40초 수준의 마이크로 브레이크만으로도 집중력 회복 효과가 측정된다. 에이전트 한 턴의 대기 시간과 규모가 같다.
- 좋은 멍 자극의 조건은 soft fascination — 느리고, 유기적이고, 약간 무작위하며, 텍스트·알림 같은 인지 부하가 없는 시각 자극. 불멍·물멍이 정확히 이 형태다.

즉 CodeMung은 "에이전트 상태 모니터"에 멍때리기를 붙인 것이 아니라, **에이전트 대기 시간이라는 자연스러운 휴식 구간을 과학적으로 좋은 멍 경험으로 채우는 것**이 본질이다. 상태 표시는 그 멍을 안심하고 때릴 수 있게 하는 장치다 — 화면을 계속 확인하지 않아도 허가 요청이나 완료를 놓치지 않는다는 신뢰.

## 무엇을 만드는가

- 투명·프레임리스 280×280 always-on-top 창과 메뉴바 아이콘
- Claude Code / Codex 훅 이벤트를 공통 모델(`idle / working / waiting_permission / completed / error`)로 정규화하고, 여러 세션의 대표 상태 하나를 장면에 반영
- 상태를 구분해 표현하는 앰비언트 모션 팩 (현재: 라바/불멍 계열)

상세 스펙과 마일스톤은 [mvp-0.1.md](mvp-0.1.md), 모션 실험 기록은 [design-log.md](design-log.md) 참고.

## 디자인 원칙

1. **저부하**: 텍스트·숫자·알림 없는 순수 시각 자극. 인지 부하가 생기는 순간 회복 효과가 사라진다.
2. **Soft fascination**: 느린 무작위성(1/f 노이즈 리듬). 완전 정적이면 지루하고, 화려하면 주의를 강탈한다. 채도와 대비는 낮게.
3. **상태는 은은하게**: 상태 변화는 장면의 분위기 변화로 전달한다. 단, `waiting_permission`과 `error`는 놓치면 안 되므로 우선순위가 가장 높다.
4. **방해하지 않음**: 훅은 앱이 죽어도 300ms 안에 조용히 성공 종료. 에이전트의 작업 흐름을 절대 막지 않는다.
5. **내용이 아닌 상태만 관찰**: 프롬프트·응답·도구 입력 본문은 저장하지도 표시하지도 않는다. 이벤트 수신은 127.0.0.1 + 토큰으로만.

## 현재 상태 (v0.1.0)

프로토타입 단계. 창·메뉴바·라바 모션 팩·reduced-motion 지원까지 동작하며, 상태는 하드코딩되어 있다. 훅 브리지, 세션 스토어, 실제 이벤트 정규화가 다음 슬라이스다.
